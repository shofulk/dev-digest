## Goal
`scope-guard.sh` stops being hardened one spelling at a time. It gets class invariants, each proven by blocked full-dispatch probes:
- every admitted Bash head is checked against one argument allowlist;
- the Bash tokenizer admits only words whose every character it models; anything else (escapes, expansions, unquoted glob characters, assignment-only segments) is rejected *(rev 4)*;
- one symlink-following resolver judges every path, and a path it cannot resolve, or any exception while judging, is denied *(rev 3)*;
- the hook allows only on one explicit evaluator exit code; a crash, a kill or any unexpected code is denied *(rev 4)*;
- the self-test never judges against the real repo root;
- the reviewer prompts point at one canonical command list instead of copying it.

## Acceptance criteria
1. **AC1: self-test isolation (P3).**

   - Rows that must touch the real root are named exceptions, listed in the helper header comment: the `CLAUDE_PROJECT_DIR`-unset/`$SELF`-fallback row, and the R5/A5 plus new whole-run tree-unchanged checks.

   - Every hook JSON payload in the self-test is built by `node … JSON.stringify`. No `printf '{"tool_input…` remains.
2. **AC2: per-head argument allowlists (P4).**
   - Every head admitted by `bash readonly` or `bash checks` is judged by one grammar table (`HEAD_ARGS`, plus `GIT_ARGS` per git subcommand, per C6):
     - boolean short flags, checked as clusters;
     - value flags, attached or as the next token;
     - exact long flags only (an abbreviated long option is rejected), each with a stated arity *(rev 3)*;
     - an operand policy.
   - Anything outside the grammar is rejected.
   - A head must be a bare command name. A head containing `/` is rejected, except the exact `CHECKS_EXACT` entries.
   - A shell invoker (`bash`/`sh`/`zsh`/`dash`) is admitted only as `-c <program>` with no further operands and no input redirection. The program is evaluated recursively. `eval` evaluates its operands joined by one space.
   - The per-spelling branches are removed: `sort -o` in `preReject`, `sort --compress-program`, `file -C`, the `uniq` operand counter, the `sed` flag checks and `sedScriptUnsafe`, `rg --pre`, `FIND_REJECT`, and the git `-c`/`--config-env`, `--ext-diff` and `grep -O`/`--open-files-in-pager` branches. *(rev 3)*
   - **Lexer invariant.** A command is rejected if any word contains a `\` or `$` outside single quotes (bare or inside double quotes), which covers `\-flag`, `$'…'`, `$"…"`, `$VAR` and `${VAR}`. It is also rejected if any word contains an unquoted `*`, `?` or `[` at any position, whatever precedes it (a literal, an empty quote pair such as `''*`, or another quoted part), or if a segment consists only of `NAME=value` assignments. A leading assignment prefix is admitted only as the exact token `CI=1` followed by a command. Single-quoted text is literal in bash, so `\`, `$` and glob characters inside `'…'` stay admitted. *(rev 4)*
   - Blocked full-dispatch rows cover every class in T5–T7, T20 and T25. No pre-existing self-test row changes its expected value, except the two evaluator-level T7 garbage-stdin rows named in AC3. *(rev 4)*
3. **AC3: one resolver, unresolvable = deny (P5).**
   - `realpathNearest` is defined exactly once, and both `bash_eval` and `write_eval` use it. Its hop limit counts symlink hops only, not parent steps.
   - Every path the guard judges goes through it and is judged on the resolved path:
     - `pnpm` positional path arguments and `-p`/`--project` values, judged against the resolved `<root>/<dir>` and outside the resolved `<root>/server/clones`;
     - `--dir`/`-C` values, which must resolve to exactly `<rootReal>/<name>`;
     - the paths inside the `CHECKS_EXACT` commands, which must resolve to exactly `<rootReal>/.claude/hooks/<file>`;
     - every write-profile path.
   - A judged path that starts with `~` or contains `$`, `*`, `?` or `[` is rejected.
   - A resolver failure (loop, hop limit, a `readlink` that throws) is a POLICY-DENY in both evaluators. So is any exception thrown while evaluating a parsed command or a parsed write payload: the hook exits 2 and never allows. This includes `write_eval`'s outer `catch`. Only unparsable hook JSON and an unresolvable project root stay fail-open. *(rev 4)*
   - **Exit protocol.** *(rev 4)*
     - Both evaluators allow by exiting one explicit allow code, `SG_ALLOW_RC` (42), defined once in the hook. The two fail-open cases also exit that code, after their stderr warning.
     - A deny writes its reason to stdout and exits 0.
     - The dispatcher allows only on `SG_ALLOW_RC`. Exit 0 blocks with the reason. Every other code blocks with a reason that names the code: node's uncaught-exception `1`, the old fail-open `3`, `127` for a missing `node`, and `128+n` for a kill.

     - Self-test helpers that call an evaluator directly map `SG_ALLOW_RC` to their `1 = allowed` value. Any other non-zero code is a mismatch, so a crashing evaluator fails every row.
