# Retro: intent-layer

Per-iteration retrospective for `docs/plans/intent-layer.plan.md`, written only by the
`retro-writer` subagent (rules: `.claude/agents/retro-writer.md`). Append-only: new class
labels and new entries go directly under their marker line, newest first. A clean
reviewer round writes nothing.

## Class labels
<!-- newest first: class-labels -->
- `acceptance-evidence-missing` — an acceptance item cannot be verified because the evidence it needs (a route loaded on a running stack, a probe run) was never produced · first seen: iteration 1 (definition reused from `review-agents.retro.md`)
- `ac-detail-unverified` — an AC/Decision detail (log line, estimate method, copy source, README note) is implemented partially or differently, and no check executed in the round exercises it · first seen: iteration 1
- `ac-rule-overlap` — two AC rules classify the same input, and the plan's derivation rule lets the wrong one fire · first seen: iteration 1
- `unenforced-budget-cap` — a cap or budget the plan specifies is declared (constant, comment) but not enforced on the path it bounds, or enforced in the wrong order · first seen: iteration 1
- `untrusted-text-sink-leak` — untrusted PR text reaches a sink (log, `pr_intent.sources`, prompt, UI) without the normalisation or delimiting the plan specifies · first seen: iteration 1
- `plan-layer-placement-gap` — the plan prescribes, accepts or leaves unstated a layer placement (file ring, instance count, route responsibility) that the onion rules reject · first seen: iteration 1
- `port-bypass` — code reaches a repository function, DB handle, container or row type directly where the plan specifies an injected port · first seen: iteration 1
- `existing-test-blast-radius` — a step changes a runtime path that existing tests exercise, and the plan does not list those tests among the step's files or checks · first seen: iteration 1
