# Development Plan: Eval Pipeline (frozen cases from triaged findings, code-only scoring, run compare)

**Spec:** `specs/eval-pipeline.md` (approved; Decisions D1–D9 pinned, not reopened) · **Packages:** server, client, e2e · **Base:** `451f2b4` (branch `L06-HW`) · **Revision:** 1

## Goal
Give every reviewer agent a regression harness built from its own triaged findings:
- one click turns an accepted or dismissed finding into a frozen eval case;
- one route runs the agent over all its cases with fixed inputs;
- code alone scores the run (recall, precision = TP/(TP+FP), citation accuracy);
- two runs of different agent versions can be compared side by side in the Agent editor and on `/eval`.

## Acceptance criteria
AC1–AC30 carry the spec's own numbering 1–30, verbatim in intent.

1. **AC1** — `POST /findings/:id/eval-case` (no body) creates an agent-owned case. The owner is `reviews.agent_id`, and the workspace check goes through the review.
2. **AC2** — The type comes from the triage decision:
   - `accepted_at` → `must_find`; `dismissed_at` → `must_not_flag`;
   - neither → `422 finding_not_triaged`;
   - review with no `agent_id` (or that agent no longer in the workspace) → `422 finding_has_no_agent`.
3. **AC3** — The case is frozen:
   - `input_diff` = the file's `pr_files.patch` wrapped in the `diff --git a/p b/p` / `--- a/p` / `+++ b/p` header. No patch → `422 no_diff_available`; more than `MAX_FROZEN_DIFF_BYTES` (200 KB) → `422 frozen_diff_too_large`.
   - `input_files = [finding.file]`.
   - `input_meta = { source_finding_id, source_review_id, pr_number, pr_title, pr_body, created_at }`.
   - `expected_output` = one `EvalExpectation { type, file, start_line, end_line, severity, category, title }`.
   - `name` = title slug plus `file:start_line`; `notes` = the rationale.
4. **AC4** — The expectation must be groundable in its own frozen diff (same rule as the gate), else `422 expectation_not_grounded`.
5. **AC5** — Idempotent: the first click returns `201`; a second click returns `200` with the same case. Lookup is `input_meta->>'source_finding_id'` + owner.
6. **AC6** — Re-triaging never mutates an existing case.
7. **AC7** — `GET /agents/:id/eval-cases` → `EvalCaseView[]`: the case, its parsed expectation, and its latest result (`pass`/`fail`/`errored`/`never_run`) from the newest completed run.
8. **AC8** — `DELETE /eval-cases/:id` → `204`; its `eval_runs` rows cascade. Workspace-scoped: another workspace's case → `404`.
9. **AC9** — `POST /agents/:id/eval-runs` (no body) → `202 { run_id, cases_total }`. Rate-limited to 5/min.
   - no cases → `422 no_cases`;
   - `!container.canUseLlm(provider)` → `422 provider_not_configured`;
   - a run already in flight for this agent → `409 run_in_flight`.
10. **AC10** — The run is identified by a minted uuid `run_id`.
    - On start, one `eval_runs` row per case: `pass = null`, `actual_output = { run_id, agent_id, agent_version, status: 'pending', … }`.
    - Each row is updated when its case finishes.
    - The run is `running` while any row is `pending`, otherwise `completed`.
11. **AC11** — Fixed inputs: `reviewPullRequest({ systemPrompt, model, strategy, skills, diff: parseUnifiedDiff(input_diff), prDescription: input_meta.pr_body, task })`, from the agent's current config and enabled skills. Never passed: repo map, callers, intent, memory, specs, session id.
12. **AC12** — Cases run sequentially in the background (fire-and-forget). A throwing case is stored as `status: 'errored'` with its reason and does not stop the run.
13. **AC13** — An eval run writes nothing to `agent_runs`, `reviews`, `findings`, `run_traces`.
14. **AC14** — A row still `pending` 15 min after its run started is reconciled to `errored` (`reason: 'timeout'`) on the next read.
15. **AC15** — `server/src/modules/eval/scoring.ts` is pure: no I/O, container or LLM import. A test asserts zero provider calls on the scoring path.
16. **AC16** — Match: exact `file`, and the line ranges intersect after min/max ordering. Only grounded findings are scored.
17. **AC17** — Per case: `must_find` passes with ≥1 match; `must_not_flag` passes with 0 matches.
18. **AC18** — Per run, over non-errored cases only:
    - `recall` = passed `must_find` ÷ all `must_find` (`null` if none);
    - `precision` = TP/(TP+FP), unlabelled findings excluded (`null` if TP+FP = 0);
    - `citation_accuracy` = Σkept ÷ Σ(kept+dropped) (`null` with no findings);
    - also `traces_passed`/`traces_total`, `cases_errored`, `duration_ms` (sum), `cost_usd` (sum, `null` if any case's cost is `null`).
19. **AC19** — Each row also carries its own `pass`, `recall`, `precision`, `citation_accuracy`, `duration_ms`, `cost_usd`.
20. **AC20** — `GET /agents/:id/eval-runs` → `EvalSuiteRun[]` newest first: `run_id`, `status`, `agent_version`, `started_at`, `finished_at`, the metrics, the case count.
21. **AC21** — `GET /eval-runs/:runId` → `EvalSuiteRunDetail` with `per_case[]`: name, expectation, pass, status, findings with a `matched` flag, kept/dropped counts. The client polls it while `running`.
22. **AC22** — `GET /eval-runs/compare?a&b` → `EvalCompare`:
    - both summaries;
    - deltas `b − a` (`null` if either side is `null`);
    - flips over the shared cases, and the cases only in one run;
    - a `system_prompt` line diff read from `agent_versions`.
    - Different agents → `422 invalid_compare`; `a === b` → `422 invalid_compare`.
23. **AC23** — `GET /eval/dashboard` → for each agent with ≥1 case: name, model, cases total, the latest completed run's metrics and `agent_version`, and the last 10 runs' recall/precision; plus the 20 most recent suite runs across all agents.
24. **AC24** — FindingCard gets a third action, "Turn into eval case" (flask icon):
    - enabled only when the finding is triaged; a tooltip explains otherwise;
    - labels the type it will create;
    - stays presentational (the parent owns the mutation);
    - toasts "Eval case created" or "Already in the eval set".
25. **AC25** — AgentEditor → Evals tab (`?tab=evals`):
    - latest-run metric tiles with deltas vs the previous run;
    - case list (name, type badge, `file:line`, last result, delete);
    - "Run evals" button, disabled with `n / total` progress while in flight;
    - run history (time, version, recall, precision, citation, passed/total, cost); exactly two selected rows enable **Compare**.
26. **AC26** — Compare modal:
    - four tiles `old → new` with signed deltas (green up, red down);
    - prompt diff (added/removed lines);
    - flipped cases.
27. **AC27** — `/eval` dashboard, linked from SKILLS LAB ("Eval Dashboard", gauge icon):
    - one row per agent (latest recall/precision/citation, version, passed/total, recall sparkline) linking to `/agents/:id?tab=evals`;
    - a recent-runs table across all agents.
28. **AC28** — All copy lives in `messages/en/eval.json`, plus `prReview` for the card button. Data comes only through `src/lib/hooks/eval.ts`. Contract imports come from `@devdigest/shared/contracts/eval-ci`, never the barrel.
29. **AC29** — `server/src/modules/eval/` is a self-contained plugin registered in `modules/index.ts`:
    - files `routes.ts`, `service.ts`, `repository.ts`, `executor.ts`, `scoring.ts`, `frozen-input.ts`, `constants.ts` (+ `helpers.ts`, C6);
    - `scoring.ts`/`frozen-input.ts` are ring-1 pure;
    - the LLM comes from the container, with no SDK import;
    - `pnpm --dir server arch` reports no new violation.
30. **AC30** — New contracts go in `server/src/vendor/shared/contracts/eval-ci.ts` and are mirrored byte-for-byte into `client/src/vendor/shared/contracts/`.
31. **AC31 — Tests gate.** `pnpm --dir server verify:l06` runs exactly:
    - `src/modules/eval/scoring.test.ts`
    - `src/modules/eval/frozen-input.test.ts`
    - `src/modules/eval/executor.test.ts`
    - `test/eval-contract-parity.test.ts`
    - `test/contracts.test.ts`
    - `test/eval.it.test.ts`

    The client RTL tests named in the spec exist and pass.
32. **AC32 — Experiment (D8/D9, manual).**
    - ≥8 cases are triaged live from Test Quality Reviewer findings on PRs #6/#8, mixing accept and dismiss.
    - Three suite runs: v1 baseline, v2 prompt edit, v3 sensitivity break.
    - Compare v1↔v2 and v1↔v3 in the modal. The v1↔v2 screenshot and the screencast are captured.

- **C6 — Planner choices inside the spec (not D1–D9 reversals).**
  - **(a) `created` flag.** `POST /findings/:id/eval-case` answers `EvalCaseCreated`, which is `EvalCase` + `created: boolean`. `api.ts` hides the status, so this is the only way the client can pick between the two toasts.
  - **(b) Extra `helpers.ts` (ring-1 pure).** It holds DTO mappers, `groupSuites`, `latestCompletedResult`, `diffLines` and the eval task line. It is added beside the seven named files: a DTO is built by a mapper, never by casting a row.
  - **(c) Per-row metrics (AC19)** apply the AC18 formulas to the single case:
    - `recall` = `1|0` for `must_find`, `null` for `must_not_flag`;
    - `precision` = TP/(TP+FP) of that case or `null`;
    - `citation_accuracy` = kept/(kept+dropped) or `null`.
  - **(d) Row timestamps.** `ran_at` stays the run's start time (never updated). `actual_output.finished_at` (ISO) is written with the terminal status.
  - **(e) Single-statement completion.** Status and metrics are written in **one** `UPDATE` per row, so a poller never sees `completed` without metrics (iS12).
  - **(f) In-flight guard.** A service-level in-memory `Set<agentId>` (synchronous check-and-add before any `await`) plus a DB check for any `pending` row of the agent after stale reconciliation.
  - **(g) Compare order.** The client always sends `a` = older run and `b` = newer run (by `started_at`).
  - **(h) Task line.** It comes from `input_meta` (`pr_number`, `pr_title`), with no timestamp, so prompts are byte-identical across runs.
- **C7 — Compare needs `agent_versions` rows.** Seeded agents never got a v1 snapshot.
  - `AgentsRepository` gains a public `ensureVersionSnapshot(row: AgentRow): Promise<void>` that delegates to the existing private `snapshotVersion(row, row.version)` (`onConflictDoNothing`).
  - `startRun` calls it before inserting rows, so every run's `agent_version` has a stored `system_prompt`.
  - In compare, a missing version yields `prompt_diff: []` plus `prompt_available: false`; it never throws.
