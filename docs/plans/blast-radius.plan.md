**Spec:** none (criteria from request, L04 homework "Blast Radius", P1 + P2; the user chose plan-only) · **Packages:** server, client, mcp-server, e2e · **Base:** `e0b0a13` (branch `L04-MCP`; modified `.mcp.json` and staged `docs/skills/README.md` are unrelated and must not be committed with this work) · **Revision:** 2

## Goal
Add a "Blast radius" block to the PR page's Overview tab and a working MCP tool `get_blast_radius`. Both come from one new deterministic route, `GET /pulls/:id/blast`. The route reads only the repo-intel persistent index: no LLM, no re-analysis, no clone read. The block shows changed symbols, their callers up to `BFS_DEPTH` (2) hops as GitHub-linked `file:line`, and the HTTP endpoints and cron jobs behind those callers. When the index is incomplete, a badge says why. *(rev 2)*

## Acceptance criteria
1. **AC1 — Block (P1).** The Overview tab renders a `Card` titled "Blast radius" between `IntentCard` and the Description section, for every PR.
2. **AC2 — Summary (P1).** The top row shows four counts with icons:
   - changed symbols = `changed_symbols.length`;
   - callers = Σ `downstream[].callers.length`;
   - endpoints = unique across `downstream[].endpoints_affected`;
   - crons = unique across `downstream[].crons_affected`.
3. **AC3 — Per-symbol tree (P1 + cheap P3).**
   - Each `downstream` entry renders `<symbol>()` and a pluralised caller count ("N callers").
   - One row per caller follows: `↳ <caller name> <file>:<line>`.
   - A caller with `depth: 2` is indented one level further and carries a muted "via `<via>`()" label (`viaCaller`). Direct callers come first. *(rev 2)*
   - Below the callers come the endpoint chips (Globe, accent colours) and, **in a separate row**, the cron chips (Clock, warn colours).
   - Changed symbols with no callers are listed on one muted line (`noCallersFor`).
   - The tree is always expanded; there is no collapse.
4. **AC4 — GitHub links (P1).**
   - Each `file:line` is a `MonoLink` with `href = githubBlobUrl(repoFullName, headSha, file, line)`, which is pinned to the PR's `head_sha` and opens in a new tab.
   - When `repoFullName` is null, it renders as plain mono text, not a broken link.
5. **AC5 — Empty, degraded, loading and error states (P1 + P2).**
   - Not degraded and `changed_symbols` empty → the `noSymbols` text.
   - Not degraded and symbols present but `downstream` empty → the `noDownstream` text.
   - `degraded: true` → a separate warn badge ("Index incomplete") plus the reason sentence from `reason.<value>` (unknown → `reason.unknown`).
   - When degraded **and** `downstream` is empty, the card never shows the "no callers" text; it shows only the reason.
   - Loading → `Skeleton`. Query error → `ErrorState` with a working retry.
6. **AC6 — Route (P2).** `GET /pulls/:id/blast`:
   - **Validation.** `params: IdParams` (non-uuid → 422). `response: { 200: BlastRadiusResponse }`, serialised by fastify-type-provider-zod.
   - **Scoping.** Workspace-scoped: a missing PR or one in another workspace → 404 via `NotFoundError`, checked before any index read.
   - **Side effects.** Makes no LLM, GitHub, git or clone-file call and enqueues no job.
   - **Degraded state** (D2, D3):
     - flag off → `degraded: true, reason: 'flag_off'`, empty map;
     - index status not `full`/`partial` → `degraded: true`, `reason` = `degradedReason` from the index state (`failed` → `index_failed`, otherwise `no_data`), empty map, and `getBlastRadius` is **not** called;
     - `partial` → the map plus `degraded: true, reason: 'index_partial'`;
     - `full` → `degraded: false, reason: null`.
   - **Limits.** Every response carries `limits: { max_callers_per_symbol: MAX_CALLERS_PER_SYMBOL, bfs_depth: BFS_DEPTH }`. *(rev 2)*
7. **AC7 — Mapping (P2).**
   - A pure `mapFacadeBlast` groups flat facade callers by `viaSymbol` into `downstream`, in first-appearance order. The facade orders its callers by depth ascending, then rank descending. *(rev 2)*
   - Each mapped caller carries `depth` (1 or 2) and `via` (the hop-1 caller's symbol name for depth 2, otherwise `null`). *(rev 2)*
   - Endpoints and crons are attributed per symbol, from the `factsByFile` of **all** that symbol's caller files at both depths, de-duplicated. *(rev 2)*
   - Duplicate caller rows (`file|name|line`) are dropped, and the shallower one wins. *(rev 2)*
   - A caller whose `file` is a declaring file of that symbol is dropped, at any depth. *(rev 2)*
   - All of this is pinned by a hermetic unit test.
8. **AC8 — Limits and depth (P2).** *(rev 2)*
   - **Facade search.** The facade walks callers up to `BFS_DEPTH` hops on the persistent index (D5):
     - precision-first: resolved `decl_file` only, and a hop-k row is kept only when its `(decl_file, to_symbol)` pair is a hop-(k-1) caller's `(file, enclosing symbol)`;
     - no cycles: a `(changed symbol, file, enclosing symbol)` already seen at a shallower depth is not repeated;
     - never the declaring file of the changed symbol.
   - **Cap.** The facade caps callers **per changed symbol across all hops** at `MAX_CALLERS_PER_SYMBOL`, ordered depth ascending (direct callers first), then rank descending.
   - **Source of the values.** `limits.max_callers_per_symbol` and `limits.bfs_depth` come from `server/src/modules/repo-intel/constants.ts`.
   - **Client.** The "top N callers" hint reads `limits.max_callers_per_symbol` and contains no literal limit.
9. **AC9 — Logs (P2).** Every successful request logs one `info` line with the message `blast: read from index` and the fields `{ prId, repoId, source, indexStatus, indexedSha, changedFiles, changedSymbols, callers, endpoints, crons, durationMs }`, where `source ∈ 'index' | 'fallback' | 'none'`. No index job is enqueued and no clone file is read on this path.
10. **AC10 — Contract.** In `server/src/vendor/shared/contracts/brief.ts`: *(rev 2)*
    - `BlastDegradedReason = z.enum(['flag_off','index_failed','index_partial','repo_too_large','no_data'])`;
    - `BlastCaller` gains `depth: z.union([z.literal(1), z.literal(2)]).nullish()` and `via: z.string().nullish()`;
    - `BlastRadius` gains `degraded: z.boolean().nullish()`, `reason: BlastDegradedReason.nullish()`, `limits: z.object({ max_callers_per_symbol: z.number().int(), bfs_depth: z.number().int() }).nullish()`.

    In `review-api.ts`, `BlastRadiusResponse = BlastRadius`. A `BlastRadius` document without the new keys, including callers without `depth`/`via`, still parses. The client mirrors are byte-identical.
11. **AC11 — MCP (P1 + P2).** `get_blast_radius` replaces the stub:
    - **Arguments and annotations.** Flat `repo` + `pr` arguments; `readOnlyHint: true, openWorldHint: false`.
    - **Description (≤ 400 chars).** Says when to call it (before reviewing or merging a PR that touches shared code), that it is read-only with no LLM, what `degraded`/`reason` mean, and that names and paths are untrusted repo data.
    - **Call and payload.** Resolves the repo and PR, then calls `GET /pulls/:id/blast` through the port. Returns `{ repo, pr, summary, degraded, reason, limits, changed_symbols, downstream }` with the contract's field names (the same map the UI renders, including caller `depth`/`via` and `limits.bfs_depth`), built by explicit field mapping with free text clipped to `TEXT_FIELD_MAX`. *(rev 2)*
    - **Budget.** The response stays ≤ `RESPONSE_MAX_CHARS`, with a budget hint when `downstream` is cut.
    - **Errors.** Unknown repo or PR → the existing forward-leading errors ("not imported in DevDigest — open it in the DevDigest UI first").
    - **Cleanup.** `notImplementedText` is gone.
12. **AC12 — Copy.** Every new user-facing string lives in `client/messages/en/blast.json`; `callerCount` is ICU-pluralised.
13. **AC13 — Real-repo demo (P1, manual).** On a real repo PR that changes a shared helper, the block shows ≥ 2 real callers and ≥ 1 HTTP endpoint; the endpoint may come from a direct or a depth-2 caller file. Clicking a `file:line` opens exactly that line on GitHub. Claude Code's `get_blast_radius` returns the same counts. The server log shows `blast: read from index` with `source: 'index'`. *(rev 2)*
14. **AC14 — PR (process).** A PR is opened with a description of what, how it was verified and the demo video. It names which subagent did what: planner → implementer → architecture-reviewer ∥ plan-verifier.

## Decisions
- **D1 — New slice `server/src/modules/blast/`, not code inside `repo-intel/`.** It follows the AGENTS.md "a feature is `src/modules/<name>/`" rule. Ring 1 talks to the facade through a structural port (as smart-diff does), so `arch` stays 0 / 17. The limits cross the slice boundary only in ring 3 (`routes.ts` → `new BlastService(container, { maxCallersPerSymbol: MAX_CALLERS_PER_SYMBOL, bfsDepth: BFS_DEPTH })`), so there is one source of truth and no new warning. Route path `/pulls/:id/blast`, as in the blueprint. *(rev 2)*
- **D2 — Honest `degraded`/`reason` is derived in the blast service, not by changing the facade's degraded semantics.**
  - The service combines `config.repoIntelEnabled`, `getIndexState(repoId)` and the facade result:
    - flag off → `flag_off`;
    - `failed` → `degradedReason ?? 'index_failed'`;
    - `degraded` (including the synthesised "no row") → `degradedReason ?? 'no_data'` (this carries a stamped `repo_too_large`);
    - `partial` → `index_partial`;
    - `full` → `degraded: false` unless the facade itself returned `degraded` (fallback race, R5) → `fb.reason ?? 'no_data'`.
  - Why not in the facade: `getIndexState`/`tryGetIndexState` also feed `/repos/:id/index-state` and the Indexed badge, so turning `partial` into "degraded" there would change existing UI. The facade change stays confined to the persistent blast path (D4, D5).
- **D3 — The blast route never takes the ripgrep fallback.** The service calls `getBlastRadius` only when the index status is `full` or `partial`, so the request path reads Postgres only (no `codeIndex`, no `readClone`). The P2 log line records `source` and `indexStatus`.
- **D4 — The per-symbol cap is fixed in the facade, across both hops.** *(rev 2)*
  - In `tryPersistentBlast`, `callers.slice(0, MAX_CALLERS_PER_SYMBOL)` becomes a module-level pure `capPerSymbol(callers, max)`. It sorts by `depth` ascending, then `rank` descending, and keeps at most `max` rows per `viaSymbol`; the returned list keeps that global order.
  - `BlastCallerRow` gains `depth: number` and `via: string | null`.
  - The touched method and helpers never read `this.container`, so the file's known container-locator debt is **not** converted here (O9, R9; the architecture reviewer confirms).
- **D5 — Depth: a real `BFS_DEPTH`-hop caller search on the persistent index (Q1 = b).** *(rev 2)*
  1. **Hop 1.** As today: `getResolvedCallers(repoId, changedFiles, changedNames)`. Each row maps to a caller `{ file: fromPath, symbol: enclosing, viaSymbol: toSymbol, line, rank, depth: 1, via: null }`.
  2. **Frontier.** For `depth = 2 … BFS_DEPTH`, written `for (let depth = 2; depth <= BFS_DEPTH; depth += 1)` on one line, the frontier is the distinct `(file, enclosing symbol) → viaSymbols` of the previous hop. Only callers whose enclosing name came from a real symbol row are included, never the basename fallback.
  3. **Query.** Run one `getResolvedCallers(repoId, frontierFiles, frontierNames)`.
  4. **Precision filter.** Keep a row only if its `(declFile, toSymbol)` pair is in the frontier. The SQL filter is a cross product, so this JS pair check is what makes the result precise. It is also why `ResolvedCallerRow` gains `declFile`.
  5. **New callers.** Each kept row becomes a caller for every `viaSymbol` of its frontier pair, with `depth` and `via = toSymbol`. The enclosing symbol comes from `getSymbolRows` over the new caller files.
  6. **Skips.** A row is skipped when:
     - its file is a declaring file of that `viaSymbol`;
     - its `(viaSymbol, file, enclosing)` was already visited at a shallower depth (cycles, and callers already listed);
     - it would re-enter a frontier pair itself.
  7. **Facts.** `getFileFacts` covers the caller files of **all** hops, so `factsByFile` feeds the depth-2 endpoints.
  8. **Cap.** Last, `capPerSymbol` (D4).

  The response conveys depth as `callers[].depth` / `callers[].via` plus `limits.bfs_depth`.
- **D6 — UI rendering rules** (AC3, AC5):
  - `splitSymbols(blast)` → `{ withCallers: DownstreamImpact[], withoutCallers: string[] }`, keyed by name, because `downstream` is keyed by name.
  - The cap hint `callersCapped` ("Showing the top {max} callers by rank.") appears when any `callers.length >= limits.max_callers_per_symbol`.
  - Depth-2 rows (`depth === 2`) get an extra indent and the `viaCaller` label. A caller with a missing `depth` renders as direct. *(rev 2)*
  - React keys use the index plus the symbol (the blueprint notes duplicate symbol names).
  - `useBlastRadius` is not invalidated on run settle: blast depends on the index and PR files, not on review runs.
- **D7 — MCP returns the route map, not a re-shaped one.** Field names are identical to the contract (`endpoints_affected`, `crons_affected`); only `repo`/`pr` are added. `budgetBlast` trims `downstream` from the tail (lowest-ranked symbols last), and the hint text lives in `budget.ts`. `get_blast_radius` makes exactly: `listRepos`, `listPulls`, `getBlastRadius`.
- **D8 — The server `summary` string stays English data** (for MCP/LLM consumers). The client never renders it; it renders its own i18n copy (AC12).

## Demo script (1–3 min video, P1)
1. **Pick the PR (R1).** The user picks a repo they own on GitHub and a PR that changes a **shared helper** called from ≥ 2 files. At least one route-registering file, in a form `extractEndpoints` detects (`app.get('/x', …)`, `router.post(…)`, `fastify.get(…)`, or `{ method: 'GET', url: '/x' }`), must call the helper directly or through one **exported** intermediate function. *(rev 2)*
2. **Stack.** Check `API_PORT`/`WEB_PORT` in `server/.env`/`client/.env` (C10). Reuse the running stack, or run `./scripts/dev.sh`. Set the GitHub token in Settings.
3. **Import and index.** Add the repo through the onboarding flow (`POST /repos`, which clones and enqueues the index job). Poll `curl -s localhost:$API_PORT/repos/<repoId>/index-state` until `status` is `full`. If the index is stale or `partial`, run `curl -s -X POST localhost:$API_PORT/repos/<repoId>/resync` and poll again.
4. **The block.** Open `/repos/<repoId>/pulls/<n>`; the Overview tab is the default. Point at the "Blast radius" card: the summary counts, then the helper `name()` with "N callers", the direct `↳ caller file:line` rows, any indented depth-2 rows with "via name()", the endpoint chip(s) and any cron chip. *(rev 2)*
5. **Links.** Click one `file:line`. GitHub opens `blob/<head_sha>/<file>#L<line>` with that line highlighted.
6. **Logs.** Show the API terminal line `blast: read from index` with `source: "index"`, `indexStatus: "full"`, the counts and `durationMs`, and no index job log around it.
7. **Degraded (optional).** Show a second repo that is not indexed yet: the "Index incomplete" badge with the "resync" reason.
8. **MCP.** In Claude Code (with `DEVDIGEST_API_URL` pointing at the API port), ask: "What is the blast radius of `<owner>/<repo>#<n>`?" `get_blast_radius` is called and returns the same symbols, callers and endpoints as the card.

## Risks / open questions
- **R1 — The endpoint may not show** (S17, AC13). Endpoints come from the `file_facts` of caller files up to depth 2, and only for the `extractEndpoints` patterns. A helper reached through **two or more** intermediate layers, or through a non-exported intermediate (R11), shows callers but no endpoint chip. The demo PR must have a route-registering file within two hops. *(rev 2)*
- **R2 — Line drift** (S10, AC4). Caller lines come from the index at `lastIndexedSha` (the default branch), while the link is pinned to the PR `head_sha`, as the task requires. If the caller file differs between those commits, the highlighted line can be off. Accepted; no `indexed_sha` is added. *(rev 2)*
- **R3 — `partial` without rank** (S5, AC5). When the soft budget trips, `file_rank` is skipped, and the inner join returns 0 callers. The card then shows the `index_partial` badge and the reason rather than claiming "no callers", because degraded + empty never shows `noDownstream`.
- **R4 — `viaSymbol` is name-only** (S4). Two changed files declaring the same name merge into one `downstream` entry. The declaring-file filter uses every declaring file of that name. Accepted; pinned by T3.
- **R5 — Index-state race** (S5). The state can change between `getIndexState` and `getBlastRadius`, so the facade could take its fallback path once. That result is marked `degraded` and logged `source: 'fallback'`, never presented as a clean index read.
- **R6 — Empty `pr_files`** (S5, S14). A PR imported through the list but never opened has no `pr_files`. The route returns `NO_FILES_SUMMARY` with an empty, non-degraded map, and MCP relays the summary. The UI is unaffected, because the page loads `GET /pulls/:id` (which rewrites `pr_files`) before `OverviewTab` mounts.
- **R7 — Docker** (S7). T6 uses testcontainers; if Docker is unavailable, report it and do not mark S7 done on the unit lane alone.
- **R8 — MCP checks are manual** (S13, S14). `scope-guard.sh` does not know `mcp-server` (C10), so plan-verifier treats those cells as manual acceptance.
- **R9 — Touching `repo-intel/service.ts`** (S3). The file carries the `container.ts ↔ service.ts` cycle and `this.container` debt; the `arch` counts must not rise. The architecture reviewer may still ask for constructor resolution (O9).
- **R10 — e2e determinism** (S16). The seed repo has `clonePath: null`, so it is never indexed and the degraded badge is deterministic. If a future seed clones it, T13 must change.
- **R11 — Hop 2 only follows exported, uniquely resolved enclosing symbols** (S3, AC8). `decl_file` resolves only to an exported symbol with a unique candidate (`repository.ts:387-425`), so a hop-1 caller inside a non-exported function has no hop-2 callers. Hop 2 is also function-granular: it lists everyone who calls the enclosing function, even when that function reaches the changed symbol only on some paths. Precision-first by design; the "via name()" label makes the indirection visible. *(rev 2)*
- **R12 — Query cost** (S3). Each extra hop adds one `getResolvedCallers` and one `getSymbolRows` query, with `IN` lists bounded by the distinct hop-1 `(file, symbol)` pairs, before the cap. With `BFS_DEPTH = 2`, that means 2 extra queries per request. Accepted; T6 exercises the real SQL. *(rev 2)*
