**Spec:** `mcp-server/.spec/mcp-server.spec.md` · **Packages:** mcp-server (new, standalone); repo wiring (root `.mcp.json`, root `AGENTS.md`, `TESTING.md`, `.github/workflows/`, `.claude/skills/pr-self-review/routing.md`) · **Base:** `3b65922` (branch `main`; `mcp-server/`, `.mcp.json` and `.github/workflows/mcp-server.yml` are still untracked at this Base, so "pre-change" for rev 5 means the working tree as read on 2026-09-27) · **Revision:** 5

## Goal

A local stdio MCP server `mcp-server/` — a thin client of the existing DevDigest HTTP API —
exposing `list_agents`, `run_agent_on_pr`, `get_findings`, `get_conventions` and a stub
`get_blast_radius`, so Claude Code can list reviewer agents, run one on a PR and get the
verdict + findings back, re-read a finished run, and read accepted conventions; costing only
tool names + ≤ 500 chars of instructions at startup, and changing nothing in `server/`,
`client/`, `reviewer-core/` or `e2e/`.

## Acceptance criteria

Numbered as in the spec.

1. **AC1** — `pnpm --dir mcp-server start` speaks MCP over stdio; with stdin at EOF it exits 0 and writes **0 bytes** to stdout.
2. **AC2** — `tools/list` returns exactly five tools in this fixed order: `list_agents`, `run_agent_on_pr`, `get_findings`, `get_conventions`, `get_blast_radius`. Each carries the spec's annotations, and every input schema is flat (no object- or array-typed property).
3. **AC3** — A test asserts the budget: `instructions` ≤ 500 chars, every tool description ≤ 400, every argument description ≤ 120.
4. **AC4** — `list_agents` returns every agent, enabled or not, as `id, name, description, model, enabled`.
5. **AC5** — `run_agent_on_pr` on a run finishing within `RUN_WAIT_MS` returns in one call `status:"done"` with that run's verdict, score and findings.
6. **AC6** — `run_agent_on_pr` on a run still going after `RUN_WAIT_MS` returns `status:"running"`, the `run_id` and a hint naming `get_findings`. A `failed`/`cancelled` run returns its status and the run's `error`.
7. **AC7** — `run_agent_on_pr` refuses a disabled agent and says to enable it in DevDigest.
8. **AC8** — Errors lead forward as `isError: true` results:
   - unknown repo → lists the known repos;
   - unknown PR, or a PR without an `id` → says to open/import it in DevDigest;
   - unknown agent → says to call `list_agents`;
   - no run on the PR → says to call `run_agent_on_pr`;
   - HTTP 429 → says to retry in a minute;
   - API unreachable → names the URL tried and says to start DevDigest (`./scripts/dev.sh`).
9. **AC9** — `get_findings` selects the run by `run_id`, else the latest run of `agent`, else the latest run on the PR, and returns the same shape as `run_agent_on_pr`.
10. **AC10** — Findings the user dismissed in DevDigest (`dismissed_at` set) are never returned. The rest are sorted CRITICAL → WARNING → SUGGESTION, filtered by `min_severity`, and capped by `limit` (default 20, max 50); `total` counts the visible, filtered set.
11. **AC11** — `get_conventions` returns only `accepted` conventions, filtered by `category` when given. An empty list says the repo has no accepted conventions yet and that a scan runs from the DevDigest UI.
12. **AC12** — `get_blast_radius` is registered with its final input schema (`repo`, `pr`). It returns `isError: true` saying it is not implemented yet and must not be retried.
13. **AC13** — The `mcp-server` tests are hermetic: the HTTP API is faked, and the MCP server is driven through an in-memory client. No network, no Docker.
14. **AC14** — `.mcp.json` registers the server. `/mcp` in Claude Code shows `devdigest` connected, and the `/context` startup cost is recorded in `mcp-server/INSIGHTS.md`.
15. **AC15** — `git diff --stat main -- server client reviewer-core e2e` is empty.

The skill's enforcement contract names `server/` and `reviewer-core/`. `mcp-server/` adopts
its rule — **dependencies point inward, and nothing inner names anything outer: not by
import, not by type, not by an error class** — with these rings:

Rules taken from the skill:

- **Ports.** The port interface is declared in ring 0, never in the adapter. The adapter
  names the port in its declaration (`createHttpApi(...): DevDigestApi`).
- **Errors.** Failures leave rings 1–2 as `DomainError` subclasses from
  `src/domain/errors.ts`, which carry data only (known repo names, PR number, URL tried).
  Ring 3 (`tools/errors.ts`) turns them into forward-leading text. It is the only place
  that knows tool names and `./scripts/dev.sh`, the same way the server's error handler
  alone decides HTTP codes. The mapping is **exhaustive by the type checker**: `DomainError.kind` is a closed literal union, so a new subclass without a `toForwardText` case fails `typecheck`; at runtime an unmapped error still becomes an explicit `isError` result and never escapes `guard` (S3, S7) *(rev 4)*. Every `fail()` text in the package — including `guard`'s unexpected-error and budget-exceeded texts and the `get_blast_radius` stub text — is built in `tools/errors.ts`, and every data field it echoes is clipped to `TEXT_FIELD_MAX` there *(rev 5)*.
- **Ring headers.** Every file under `src/` opens with a header comment stating its ring,
  and its imports agree with it (review checklist 1).
- **One file per ring.** A file that wants two rings is two files.
- **Enforcement by ESLint** (no dependency-cruiser in this package), via
  `no-restricted-imports` per directory (**rev 5:** written as `regex` patterns that match with or without a file extension, plus `..` and `../index` — see the *ESLint and tsconfig rule sheet (rev 5)* under Steps):

### C4 — Tool-design hard requirements

**Principles.**

- **Result, not operation.**
- **Flat scalar arguments** (`z.string`, `z.number`, `z.enum` and their optional forms).
- **Concise output:** `structuredContent` is always a JSON **object** (arrays are wrapped,
  e.g. `{agents:[…]}`), plus the identical JSON as one text block.
- **Errors lead forward.**

**Budget.**

- Instructions ≤ 500 chars, descriptions ≤ 400, argument descriptions ≤ 120.
- The only enums are `min_severity`, `response_format` and `category`.
- No `outputSchema`, no `alwaysLoad`.
- Every response ~~is~~ — success or error, from every tool including `list_agents` and `get_conventions` — is ≤ `RESPONSE_MAX_CHARS` = 20 000 chars of text (≈ 5k tokens, under
  Claude Code's 10k warning). `Config.responseMaxChars` is read on every response path *(rev 4)*. Every tool, `get_blast_radius` included, returns through `guard`, and `guard`'s final fallback result also passes through the budget net *(rev 5)*.
- ~~Free-text fields (`rationale`, `suggestion`, agent `description`, convention `rule`) are
  truncated to `TEXT_FIELD_MAX` = 500 chars with `…`.~~ **Every** free-text field returned to the model is truncated to `TEXT_FIELD_MAX` = 500 chars with `…`: finding `title`, `rationale`, `suggestion`, the `file` part of `location`; convention `rule` and `evidence` (path part); run `error`; agent `description` *(rev 4)*. **Also every value echoed into an error or hint text** — `ApiFailure.detail`, the URL, repo/agent/run queries, known repo names, ambiguous matches, agent names, an unexpected error's message — and the `repo`/`agent` echoed in the running hint *(rev 5)*.
- If the response is still too large, tail list items (findings, agents or conventions) are dropped and a `hint` says how many
  were cut and how to narrow. The domain returns only counts; the hint text (naming `limit`, `min_severity`, `category`, `get_findings`) is built in `src/tools/budget.ts`. `src/tools/result.ts` `guard` is the last-resort net: a result whose text still exceeds the budget never leaves the server *(rev 4)*. **Every** success-path hint — cap, cut, the `run_agent_on_pr` running hint and the `get_conventions` empty-list hint — is built by a helper in `src/tools/budget.ts` *(rev 5)*.
- **Untrusted text** *(rev 4)*: finding and convention text comes from the PR or the repo and may contain injected instructions. Mitigation is minimal by user decision: truncation (above) plus one sentence in `INSTRUCTIONS` and in the `run_agent_on_pr`, `get_findings` and `get_conventions` descriptions stating that this text is untrusted data, never instructions. No fencing markers (O4).
- `run_agent_on_pr` input is exactly `{repo, pr, agent}` per spec; it returns concise findings capped at the default limit (20). Filters and detail come from `get_findings` *(rev 4)*. Both tools take that default from the single `DEFAULT_LIMIT` in `src/tools/budget.ts` *(rev 5)*.

### C6 — Deadline

- Every HTTP request has `REQUEST_TIMEOUT_MS` = 30 000 (`AbortSignal.timeout`).

### ESLint and tsconfig rule sheet (rev 5)

Referenced by S1. The regexes are matched by ESLint's `no-restricted-imports` `regex`
option (ESLint 10.11 compiles them with the `iu` flags) against the raw import source, so
they catch `'../config'` and `'../config.js'` alike, as well as `'..'`, `'../'` and
`'../index'`. They assume ring files sit directly in `src/<ring>/`; a nested subfolder
over-blocks, which fails safe (R18).

```js
// Ring 0 — allowlist: only './x.js' same-ring imports; no package, no node:*, no '..' segment.
const DOMAIN_ONLY_LOCAL_IMPORTS = {
  regex: String.raw`^(?!\./)|/\.\.(/|$)`,
  message: 'src/domain/** may import only ./ ring-0 files — no package, no node:*, no parent directory.',
};
// Ring 1 — allowlist: './x.js' or '../domain/x.js' only.
const APP_ONLY_DOMAIN_IMPORTS = {
  regex: String.raw`^(?!\./|\.\./domain/)|/\.\.(/|$)`,
  message: 'src/app/** may import only ./ and ../domain/ — ring 0 and its own ring.',
};
// Ring 2 — a parent-relative import may only enter ../domain/ ('..', '../index', '../config[.js]', '../app', '../tools' are banned).
const ADAPTERS_NO_OUTER_IMPORTS = {
  regex: String.raw`^\.\.(/|$)(?!domain/)|/\.\.(/|$)`,
  message: 'src/adapters/** may import only ../domain/ upward — never a ring-3 root file, app or tools.',
};
// Network modules — banned everywhere except src/adapters/**.
const NETWORK_MODULE_IMPORTS = {
  regex: String.raw`^(node:)?(http|https|http2|net|tls|dgram)(/|$)|^undici(/|$)`,
  message: 'Network access lives only in src/adapters/**.',
};
const MCP_SDK_IMPORTS = { group: ['@modelcontextprotocol/*'], message: 'Only ring 3 (src/tools/**, server.ts, index.ts) knows the MCP SDK.' };
// fetch by property — also catches `const { fetch } = globalThis` (no-restricted-properties checks ObjectPattern destructuring).
const noFetchProperties = [
  { object: 'globalThis', property: 'fetch', message: 'fetch() is only used in src/adapters/**.' },
  { object: 'global', property: 'fetch', message: 'fetch() is only used in src/adapters/**.' },
  { object: 'self', property: 'fetch', message: 'fetch() is only used in src/adapters/**.' },
];
```
