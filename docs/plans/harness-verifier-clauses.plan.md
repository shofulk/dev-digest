## Goal
plan-verifier returns `met` for a behavioural clause only when the evidence cites the test (`file › it`) and the assertion line that exercises that clause. It also gains a separately counted `awaiting manual` verdict for checks that only the user can run, or that need a browser channel the session does not have. The README and the `/sdd-run` triage both use that verdict.

## Acceptance criteria
1. **AC1** — In `.claude/agents/plan-verifier.md`, a behavioural AC clause or step detail is `met` only when the verdict cites the `file › it` AND the assertion line that exercises that specific clause; a test whose title claims a clause it does not assert is `partial` (evidence: pr-brief T7 title claimed Regenerate force:true but never clicked it; plan-verifier.md:65-67, :131-139).
2. **AC2** — A new verdict `awaiting manual` for items only the user or an absent browser channel can run (visual checks, axe/keyboard); counted separately in the Summary line and not re-raised as a gap each round.
3. **AC3** — `.claude/agents/README.md` reflects the new verdict where it documents the verifier's verdicts / Inputs table (~:310) and *Manual acceptance* (~:159-167), and `.claude/skills/sdd-run` triage.md maps `awaiting manual` (it currently routes `cannot verify` to Phase 3 manual acceptance).
