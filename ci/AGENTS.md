# `@devdigest/ci` — the CI runner

One bundled ESM file, `ci/dist/index.js`, that an exported agent bundle runs inside a
repository's GitHub Actions: it reviews the pull request with every exported agent and
writes `devdigest-result.json`.

## Read when

- Purpose, the build, the env contract, error codes → `./README.md` (source of truth).
- Starting any work here → `./INSIGHTS.md` first; at the end of the task run
  `engineering-insights` to append what is worth keeping (append-only).
- Implementing a feature → `specs/export-to-ci-mvp.spec.md`.

## Commands

`pnpm --dir ci typecheck` · `pnpm --dir ci lint` · `pnpm --dir ci test` (vitest) ·
`pnpm --dir ci build` (writes `ci/dist/index.js`).

## Conventions

- **One ESM file.** `src/index.ts` is the only file that touches `process`, `node:fs` or
  `fetch`; `src/run.ts` holds all logic with injected dependencies.
- **Secrets come from the environment and are never logged.** Every log line passes a
  redactor that masks the key and the token.
- **reviewer-core's public surface only** (`reviewPullRequest`,
  `toReviewPayload`, `countBlockers`, `OpenRouterProvider`). Never
  change `reviewer-core/` from here.
- **`run.ts` imports the server's diff parser by relative path**
  (`../../server/src/adapters/git/diff-parser.ts`). It is the same parser the studio's
  grounding uses, so a second copy could drift; it is pure (a type-only import of
  `@devdigest/shared`), so the bundle stays free of server code. `ci-runner.yml` watches
  that path.
- Third-party packages (`zod`, `openai`, `yaml`) resolve only from `ci/node_modules`.
- Every test runs without network: inject fakes.

## Do not touch

`dist/` — generated by `pnpm --dir ci build`, gitignored.
